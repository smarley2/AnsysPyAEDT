# Canonical catalog data

Human-reviewed source records for commercial cores and round-wire conductors.

- YAML files here are the review surface; edit and review them, never the SQLite index.
- `tools/build_catalog.py` compiles this directory into `artifacts/catalog/catalog.sqlite`
  (gitignored build artifact — never edit or commit it).
- Field names and units match `schemas/catalog/*.schema.json`: meters, camelCase.
- `reviewStatus: draft` marks values transcribed but not yet verified against the
  cited source page. Only a human reviewer may set `reviewStatus: reviewed` and
  `reviewedBy`, after checking every number against the source.
- `catalog/conductors/round-wire.yaml` is generated by `tools/generate_conductors.py`;
  regenerate it instead of editing by hand, then review and commit the result.

## Canonical source data versus a user's own cores

The YAML here is the reviewed, shipped catalog: it is compiled into
`artifacts/catalog/catalog.sqlite` at build time and every installed copy
carries the same records.

A user of the installed application adds cores a different way, and never by
editing this directory: the Core & Material screen imports a filled core
template into `%LOCALAPPDATA%\InductorDesigner\catalog-overlay\cores`, one
JSON file per core, read as a layer over the shipped index (see
`docs/superpowers/specs/2026-09-04-user-core-catalog-design.md`). Those
records are always `reviewStatus: draft`, because the rule above still holds:
only a human reviewer may set `reviewed`, after checking every number against
the cited source page. An import is not that reviewer.

A core that belongs in the product -- one BRUSA will use again -- is promoted
by adding it to the YAML here and reviewing it, not by leaving it in someone's
overlay.
